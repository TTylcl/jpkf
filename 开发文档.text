二、核心架构：LangGraph Router 路由模式

请求流：
  POST /api/chat_stream
    → 用户身份识别（DB 查 user_type → 映射 agent_role）
    → 会话管理（创建/查找 SessionInfo，加载历史消息）
    → Graph 执行：
        START → permission_check → prefetch_children → classify_intent
          → 路由:
              parent_schedule → schedule_agent (ReAct 循环)
              parent_course   → course_rag_agent (ReAct 循环)
              general         → parent_service_agent (ReAct 循环)
    → 消息持久化（save_user_message + save_ai_message）
    → SSE 流式返回（text / tool_start / tool_end / done / error）

Agent 路由表（INTENT_TOOL_MAP）：
  - parent_schedule: get_my_children, get_child_schedules（2个工具）
  - parent_course: rag_search, query_courses, get_course, get_child_courses, get_my_children（5个工具）
  - general: 角色权限矩阵中的所有工具

角色映射（ROLE_MAP）：
  ADMIN → edu_admin_agent / TEACHER → teacher_agent
  STUDENT → student_agent / PARENT → customer_service_agent


三、消课模块 [v5新增]

3.1 业务流程

  上课时间到 → 调度器每分钟扫描匹配排课
    → 创建教师待办（TeacherTodo）+"待消课提醒"通知
    → 发送"上课提醒"通知给教师+学生
    → 教师调用 consume_lesson(schedule_id, student_id) 确认消课
      → 验证：排课存在、教师身份、学生已报名、剩余课时>0
      → remaining_lessons -= 1（归零自动标记 completed）
      → 创建 LessonConsumption 记录（保留教师/学生/课程/时间戳）
      → 标记 TeacherTodo 为已完成
      → 发送"消课完成通知"给家长+教师

3.2 数据表

  lesson_consumption: 每次消课一条记录，含 schedule_id/course_id/teacher_id/student_id/consumed_at
  teacher_todo: 教师每日待办，含 todo_date/title/status (pending→done)
  notification: 通知表，含 recipient_id/notification_type/is_read
  student_schedule: 学生-排课关联，每人每周固定1-2个时段

3.3 权限（4角色）

  customer_service（家长）: 只能看通知，不能消课
  teacher_agent: consume_lesson, query_consumption_history, get_my_todos, mark_todo_done
  edu_admin_agent: 全部权限
  student_agent: 只能看通知


四、跨层调用规则

  api/routers → agent/ + service/
  agent/ → core/graph/ + core/service/
  core/graph/tools/ → service/（桥接层，不写业务逻辑）
  service/ → dal/dao/ + dal/query/ + dal/models/ + infrastructure/
  dal/ → dal/models/ + infrastructure/

  禁止反向依赖：下层不许调上层。


五、Service 层开发规范

  类结构: resource + dao_class 类属性
  方法装饰: @tool(ToolMeta(name, description, parameters, require_permission, sensitive_output))
  返回类型: Schema | ServiceResult（简单成功→Schema自动包装，错误→ServiceResult.error）
  DAO获取: get_dao(ctx, dao_class) 统一方式
  复杂查询: QueryService（多表关联+分页排序），简单查询直接用 DAO


六、权限系统

  定义在 core/service/models.py 的 AGENT_PERMISSIONS_MATRIX
  4个角色 × 10个资源（含消课模块3个新资源）× 细粒度操作白名单
  @tool 装饰器自动检查，方法内部无需手动检查权限


七、ServiceResult 数据模型

  success: bool / code: int / message: str / data: Any / trace_id: str
  工厂: ServiceResult.ok(data, message, trace_id) / ServiceResult.error(message, code, trace_id)
  @tool 行为: 非ServiceResult→自动包装 / 异常→自动捕获500 / sensitive_output→自动脱敏


八、开发流程

  新增 Service 方法:
    1. 在 service/xxx_service.py 添加方法 + @tool(ToolMeta(...))
    2. ToolMeta.name 在权限矩阵注册
    3. 类型标注 Schema | ServiceResult
    4. 通过 get_dao() 或 QueryService 获取数据

  新增完整 Service:
    1. service/xxx_service.py（resource + dao_class + @tool方法）
    2. 在 core/graph/tools/loader.py 的 SERVICE_INSTANCES 注册
    3. 在 core/service/models.py 权限矩阵添加条目
    4. 在 core/prompt_templates/base_templates.py 添加说明
    5. 编写 test/service/test_xxx_service.py


九、核心设计决策

  - 学生→排课映射: 通过 student_schedule 表绑定，每人固定时段
  - 消课触发: 调度器自动生成待办，教师手动确认（防止误扣）
  - 通知覆盖: 课前(CLASS_REMINDER) + 课后(CONSUMPTION_PENDING) + 消课完成(CONSUMPTION_COMPLETED)
  - 权限: 消课只有任教教师能执行（验证 schedule.teacher_id == ctx.user_id）
  - 防重复: schedule_id + consumed_at 日期级别，同一排课同一天不能重复消
  - 查询优化: schedule_query_service 通过 student_schedule 子查询聚合学生姓名
