## 二、本次会话修改总结

本次会话共修改 **14 个文件**，涉及课程创建、排课查询、预排课、数据序列化、Intent 分类等多个模块。

### 2.1 课程创建引导流程修复

**问题**：Agent 在用户只说"生成钢琴大师课，让周明远老师教"时，直接调用 `create_course` 把 price=0、total_lessons=0、description="" 全填默认值，没有询问用户。

**修改文件**：
- `core/prompt_templates/base_templates.py` — ADMIN_PROMPT 重构为三步引导流程（信息收集→汇总确认→创建），price/total_lessons/description 从"建议项"升级为"必须确认项"
- `service/course_service.py` — `create_course` 工具描述加 ⚠️ 前置条件警告

**修复后**：Agent 查完教师后，会逐项询问价格、课时、描述，汇总确认后才调 `create_course`。

### 2.2 课程查询路径数据对齐

**问题**：四条课程查询路径返回给 LLM 的内容完全不同——`query_courses` 返回完整数据，`get_course` 只返回 `repr` 字符串，`get_child_courses`（家长）缺价格/教师，`get_my_courses`（学生）只返回 `repr` 无任何结构化数据。

**修改文件**：
- `schemas/student_course_schema.py` — `StudentCourseResponse` 加 5 个字段：`course_type`、`teacher_name`、`price`、`total_lessons`、`description`
- `service/student_course_service.py` — `get_my_courses` 从裸 ORM 改为走 `StudentCourseQueryService` + Schema 映射
- `service/course_service.py` — `get_course` / `get_course_by_code` 改为返回 `course.to_dict()`
- `dal/models/course_model.py` — `to_dict()` 修复：`course_type` 枚举 → `.value` / `.label`，删除无效字段

**修复后**：四条路径返回的课程核心字段（名称、价格、课时、教师、类型、描述）完全对齐。

### 2.3 预排课流程重构

**问题**：家长问"赵一辰周四 17:30 能排课吗"，系统查 `schedule` 表的现成空位 → 没有 → 说"没空位"。正确逻辑应该是：查报名 → 查剩余课时 > 0 → 查教师空闲 → 提交预排课。

**修改文件**：
- `service/schedule_service.py` — 新增 `check_teacher_availability` 工具（反向查：教师在此时间没有课 = 空闲）
- `service/pre_schedule_service.py` — `submit_pre_schedule` 加剩余课时 > 0 校验
- `core/service/models.py` — 权限矩阵加 `check_teacher_availability`
- `core/prompt_templates/base_templates.py` — PARENT_SERVICE_PROMPT 重写为"查报名→查空闲→提交预排课"三步，明确家长永远走预排课

**修复后**：家长排课判断依据 = 报名 ✅ + 剩余课时 > 0 ✅ + 教师空闲 ✅。

### 2.4 教师空闲检查双表覆盖

**问题**：`check_teacher_availability` 只查 `schedule` 表，没查 `pre_schedule` 表的 PENDING 记录。预排课申请应该也占时间，防止同一教师同时段被多个家长申请。

**修改文件**：
- `service/schedule_service.py` — `check_teacher_availability` 和 `create_schedule` 都加了 pre_schedule PENDING 遍历 + `_parse_preferred_time()` 正则解析
- 新增 `_parse_preferred_time` 辅助函数，解析 `"周四 17:30-18:30"` 格式

**修复后**：教师空闲 = schedule 表无冲突 AND pre_schedule 表无 PENDING 冲突。

### 2.5 审核预排课自身冲突修复

**问题**：审核预排课 ID=60 时，遍历 PENDING 列表找到了自己 → "与预排课 ID:60 冲突"，自己把自己拦住了。

**修改文件**：
- `service/schedule_service.py` — `create_schedule` 加 `_exclude_pre_schedule_id` 内部参数
- `service/pre_schedule_service.py` — `review_pre_schedule` 传 `_exclude_pre_schedule_id=pre_schedule_id`

**修复后**：审核通过时排除自身的 PENDING 记录。

### 2.6 Prompt 花括号转义修复

**问题**：PARENT_SERVICE_PROMPT 里写了 `{课程名}` 和 `{教师名}` 作为 LLM 示例文本，但 Python `.format(agent_role=..., user_role=...)` 把它们当成占位符 → `KeyError: '课程名'` → 所有角色所有请求全部挂掉。

**修改文件**：
- `core/prompt_templates/base_templates.py` — `{课程名}` → `{{课程名}}`，`{教师名}` → `{{教师名}}`

**修复后**：系统恢复正常。

### 2.7 审核通过后学生入排课表

**问题**：审核预排课通过后，`create_schedule` 创建了排课，`StudentCourse` 确认了报名，但**没有写 `student_schedule` 表**。老师查排课显示"学生暂未添加，共 0 人"。

**修改文件**：
- `service/pre_schedule_service.py` — 审批通过流程新增步骤 ⑥：`StudentScheduleDao.create(student_id, schedule_id)`

**修复后**：审核通过后学生自动出现在排课表里。

### 2.8 全局裸 ID 审计和修复

**问题**：系统返回给 LLM 的错误消息和 Schema 数据中大量使用裸数字 ID（`学生{student_id}`、`课程{course_id}`、`教师 #{teacher_id}`），LLM 看不到人名/课程名就无法给用户友好的回复。

**修改文件（10 个）**：
- Schema 层：`SubmitResponse` +`student_name`/`course_name`；`ReviewResponse` +`student_name`/`course_name`/`teacher_name`；`EnrollResponse` +`student_name`/`course_name`
- `service/schedule_service.py` — 错误消息教师名/课程名，`check_teacher_availability` 返回加 `teacher_name`
- `service/pre_schedule_service.py` — 绑定/报名/课时错误消息加学生名+课程名
- `service/lesson_consumption_service.py` — 消课通知换成人名+课程名
- `service/course_service.py` — `课程不存在: X` → `课程#X不存在`
- `service/user_service.py` — `用户不存在: X` → `用户#X不存在`
- `service/parent_student_service.py` — 绑定错误加 ID 标注
- `service/student_course_service.py` — `课程不存在: X` → `课程#X不存在`
- `service/teacher_todo_service.py` — `待办不存在: X` → `待办#X不存在`
- `service/notification_service.py` — `通知不存在: X` → `通知#X不存在`

**修复后**：所有返回给 LLM 的信息优先显示可读名称，ID 仅做标注。

### 2.9 IntentResult 序列化警告修复

**问题**：Pydantic 日志输出 `UserWarning: Expected 'none' but got 'IntentResult'`。

**修改文件**：
- `core/graph/nodes/classify_intent.py` — LLM 分类路径显式 `del result`；意图复用路径加 `isinstance` 防御

**修复后**：纯值提取保证不泄露 Pydantic 对象到 state。

## 三、架构评价

### 3.1 架构设计亮点

**1. Router 模式**
```
permission_check → prefetch_children → classify_intent → 6 路 Agent
  ├── parent + schedule → schedule_agent
  ├── parent + course   → course_rag_agent
  ├── parent + general  → parent_service_agent
  ├── admin             → admin_agent
  ├── teacher           → teacher_agent
  └── student           → student_agent
```
每个 Agent 独立的 prompt + 工具白名单，注意力隔离。非 parent 角色在分类层短路省 LLM 调用。

**2. `@tool` 装饰器体系**
`ToolMeta` + `@tool` 装饰器统一权限校验、日志、异常处理、脱敏。`build_langchain_tools` 反射自动发现所有 `@tool` 方法 → LangChain StructuredTool，新增工具零配置。

**3. CTX 设计**
`AgentContext`（LangGraph Runtime）和 `CTX`（Service 层带 DB session）分离。`frozen=True` 防篡改，`trace_id` 全链路追踪。

**4. 权限矩阵集中管理**
`AGENT_PERMISSIONS_MATRIX` 四角色权限一目了然，资源级操作白名单。

**5. 消课 + 通知 + 待办闭环**
调度器每分钟扫描 → 生成待办 → 教师消课 → 扣课时 → 通知家长。

**6. 软删除统一处理**
`SqlalchemyBaseDAO._apply_deleted_filter()` 自动过滤软删记录，所有查询默认排除已删除数据。

**7. ServiceResult 统一返回**
`ServiceResult.ok()` / `ServiceResult.error()` 统一格式，`__str__` 自动处理 Pydantic/ORM/dict 序列化。

**8. 流式 SSE 输出**
`/chat_stream` 接口逐 token 推送 + 工具调用开始/结束事件，前端可以实时渲染。

## 七、剩余风险

1. **`_parse_preferred_time` 正则脆弱** — 只匹配 `周X HH:MM-HH:MM` 格式。如果格式变化或 Agent 生成了其他格式，冲突检查静默跳过，可能导致真实时间冲突。建议在 `pre_schedule` 表加结构化时间字段。

2. **Prompt `.format()` 无自动化保护** — 目前靠人工检查。建议加 CI 步骤：对 `base_templates.py` 所有 prompt 字符串执行 `.format(agent_role="t", user_role="t")`。
